## 系統範圍與架構

提供學生點餐、商家接單備餐與管理員管理查詢。單一校園、繁體中文、Asia/Taipei；付款由現場處理，系統不包含金流、退款、收款狀態或財務對帳。

先採 React + TypeScript 前端、NestJS 模組化單體後端、單一 PostgreSQL，另以共用程式碼的 Worker 執行通知、逾時取消與恢復工作。瀏覽器透過 HTTPS 呼叫 API；後端負責授權、價格、資源及狀態判斷。郵件僅供登入驗證。

完整關係見 [圖 0：全系統 UML 架構總覽](./SAD/00_系統架構與模組分工.md#圖-0-全系統-uml-架構總覽)。

## 四條主要流程

| 流程 | 核心做法 |
| --- | --- |
| 登入 | 寄六位一次性碼；驗證成功才建立登入。每次受保護請求重新檢查帳號、角色及資料範圍 |
| 送單 | 購物車與報價不占資源；提交後重驗內容、三張上限、供應與截止，訂單、庫存、容量、快照及成功結果同交易提交；失敗整單回滾 |
| 訂單操作 | 待商家確認 → 製作中 → 可取餐 → 已完成；合法取消轉已取消。未取由商家在時段結束後、已備妥且未交付時標記；終止狀態不再轉換 |
| 通知與刪除 | 需通知的事件同交易寫入 Outbox，提交後去重投遞。學生無進行中訂單才可刪帳號及全部訂單；還原備份前須重套刪除，不能讓資料復活 |

訂單生命週期見 [圖 6：訂單狀態圖](./SAD/06_訂單與交易_Orders.md#圖-6-訂單狀態圖)。

## 不可違反的規則

- 同一次送單或訂單狀態操作重送，回原結果；未知結果沿原識別查詢，不能換識別重建。詳細結果保存 24 小時，過期識別不重新執行。
- 庫存及容量在建單時保留。接單前取消退原營業日庫存及容量；接單後取消只退容量；完成與未取都不退資源。
- 容量按餐點份數計算，新增占用及容量修改均不得使占用超過容量；低於占用的容量修改被拒，原設定維持。預訂固定於時段開始前 10 分鐘截止，商家不可調整。
- 商家停用取消全部進行中訂單；待商家確認到取餐時段結束即符合系統取消條件。製作中及可取餐不因時段結束而自動取消，系統不自動標記未取。
- 營業日結束後不能再核碼完成或把製作中改成備妥；商家僅能取消，或對已備妥未交付者標記未取。
- 取餐碼只供本人學生查看；商家選定訂單後輸入核對，管理員也不可讀碼。已成立訂單的商品名稱與商品單價採成立快照。
- 個資刪除後統計依現存訂單重算；歷史資源占用不因刪除被誤加回。操作紀錄保留，但解除學生及已刪訂單的可識別關聯。

## 審查決議摘要

依 2026-11-02 指示先採以下建議方向；Q6 效期已採用為本版設計值；Q5、Q7 已於 2026-11-26 定案。

| 優先 | 問題 | 採用方向 |
| --- | --- | --- |
| P0／Q1 | 刪除途中當機或刪除復原日誌失敗怎麼恢復？ | 持久刪除請求、封鎖存取、刪除復原日誌與可重試清除；完成後才回成功 |
| P0／Q2 | 誰負責商家停用的共同交易？ | 由應用層協調入口管理，避免 Merchant 與 Orders 直接互相依賴；預覽變動須重新確認 |
| P0／Q3 | 學生確認報價的紀錄怎麼保存？ | 採建單時確認；不可讓新報價或清理作業破壞仍有效的確認與恢復 |
| P1／Q4 | 已使用時段能否實體刪除？ | 已使用或有引用者禁止刪除，從未使用且無引用者才可刪除；此規則已取代原封存方案 |
| P1／Q5 | 採哪套環境、誰維運？ | 模擬交付：Docker Compose 單機部署、單一 PostgreSQL 加 WAL 歸檔、Mailpit 收信；所有角色由專案負責人擔任 |
| P1／Q6 | 登入多久到期、共用帳號怎麼用？ | 學生 24 小時／閒置 30 分鐘；商家 12 小時／60 分鐘；管理員 8 小時／15 分鐘 |
| P1／Q7 | 取消與恢復多久內必須完成？ | 時段結束後 2 分鐘內完成、恢復後 5 分鐘內補完；掃描 30 秒、領取時限 60 秒、重試 5 次；SRS FR-027 已加註 |

詳細原因、實際情境、選項及來源見 [審查結果與決議事項](./SAD/審查紀錄.md#最需要先確認的事項)。SRS 已決定的業務規則不需重選；採用方向與定案已記錄，實測結果仍須補齊。

## 驗證與下一步

以真實 PostgreSQL 驗證並行送單、資源不足回滾、接單與取消競爭、重試去重、商家停用及個資刪除／恢復。500 人情境下，指定一般操作 p95 ≤ 3 秒、錯誤率 < 1%，正常前景狀態更新 95% 在 10 秒內；月營業時段可用率目標 99%、RPO 15 分鐘、RTO 4 小時。

依採用方向及剩餘參數完成 OpenAPI、資料庫 migration、模組實作與驗收測試。本次已檢查文件與圖表，尚無應用程式效能或故障恢復實測結果。
