# 校園點餐系統｜前端架構

> SAD v0.6｜2026-11-02｜需求基線 SRS v0.6｜設計採用版（待實作驗證）

[回 SAD 索引](../校園點餐系統_SAD_v0.6.md) · [上一份：共用 API 與錯誤契約](./11_共用API與錯誤契約.md) · [下一份：部署維運與驗證](./13_部署維運與驗證.md)

前端按 `auth`、`menu`、`cart`、`student-orders`、`merchant-console`、`admin` 分區，共用 HTTP client、錯誤翻譯、表單驗證及設計元件。前端快取用於顯示；商品上下架、商品單價、庫存及訂單狀態由後端定案。

| 畫面 | 狀態與必要行為 |
| --- | --- |
| 登入 | 寄送中、已寄送、過期、驗證失敗、停用；不可因郵件請求成功就視為登入 |
| 菜單 | 載入中、無商品、載入失敗；成功時以文字清單顯示上架商品名稱、商品單價及庫存提示，無圖片或分類；下架商品隱藏，後端菜單回應亦不包含該商品；舊畫面加入或舊購物車送單仍由後端重驗；庫存不足不改變商品狀態 |
| 購物車 | 編輯中、報價改變、庫存不足、時段額滿；跨店更換明確確認 |
| 送單 | 草稿、送出中、結果待確認、已成立、已知拒絕；送出中固定 key，不重新產生 |
| 訂單詳情 | 顯示六狀態、不可變明細、時段及允許命令；衝突後刷新，不樂觀宣告完成 |
| 商家交付 | 輸入取餐碼及「已實際交付」確認；錯碼或版本衝突保持原狀態 |
| 商家工作台 | 待確認、製作中、可取餐分列；斷線及過期資料有明顯提示 |
| 商品管理 | 商家可查看本店上架及下架商品，編輯商品名稱、商品單價與上架／下架；修改使用商品資料版本防止覆寫，庫存管理另行設定當日可用量與每日預設量，均為非負整數 |
| 取餐時段管理 | 預訂截止固定提前 10 分鐘，無截止分鐘數輸入；容量低於已占用份數時提示原因並保留原設定；已使用時段不提供刪除操作，後端亦重新檢查 |
| 管理查詢 | 空資料與載入失敗不同；統計顯示口徑版本與截至時間 |

**D-06：正常連線且頁面在前景時，以約 5 秒為起始輪詢間隔並加入小幅抖動**。單一頁面合併讀取必要的狀態摘要，避免每張訂單各發一個輪詢。切回前景及網路恢復時立即刷新；背景頁面可降低頻率，須標示最後更新時間。10 秒可見性測試應明確限定正常連線與核定瀏覽器前景情境，依 SRS v0.6 NFR-003 量測 95% 的狀態變更。

輪詢間隔、API 時間與畫面處理加總才是端到端延遲，不以「5 秒輪詢」直接宣稱達成 10 秒要求。離線期間不提供自動排隊送單；恢復後先查詢原操作結果。

## 登入到期的畫面處理

依 [Session 效期與多裝置策略](./01_身分與帳號_Identity.md#session-效期與多裝置策略)，到期前 2 分鐘提示，輪詢與新單通知不得自動續期。收到 401 SESSION_EXPIRED 時清除私人資料與取餐碼並引導收碼登入；Session 過期本身不取消訂單。同帳號重新登入後先查原送單／命令結果，再恢復畫面，不能自動換 key 重送。明確按「繼續使用」可更新尚有效 Session 的閒置時間，不能延長絕對效期。
